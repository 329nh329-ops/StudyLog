# StudyLog テスト仕様書

このドキュメントは、StudyLogのBackend・Frontendで「何を」「どのような観点で」テストしているかをまとめたものです。テストの実行コマンド自体は [README.md のテスト節](../README.md#テスト) を参照してください。

## Backendテスト（pytest、5ファイル・97件）

Backendのテストは、実際にFastAPIのTestClient経由でHTTPリクエストを送り、レスポンスのステータスコード・ボディを検証するブラックボックステストです。DBは本番用の`studylog`データベースを直接使用し、各テスト実行後に全テーブルをTRUNCATEします（[docs/incidents/2026-08-past-development-gotchas.md](incidents/2026-08-past-development-gotchas.md)参照）。

### test_auth.py（12件）：認証

- ユーザー登録の正常系・異常系（ユーザー名重複、パスワード確認不一致、パスワード強度不足）
- ログインの正常系（Cookieが正しく設定されること）・異常系（パスワード誤り、存在しないユーザー名でも同じエラーメッセージになること）
- `/api/auth/me`の認証必須確認、ログイン中ユーザー情報の取得
- ログアウトのCSRF必須確認、Cookie削除の確認、CSRFトークン不一致時の拒否

### test_categories.py（26件）：カテゴリ管理

- 一覧取得（論理削除済みを除外すること、USER/ADMINどちらでも閲覧可能なこと）
- 追加・変更・削除のADMIN権限必須確認、CSRF必須確認
- カテゴリ名の重複制約（未削除カテゴリの中でのみ一意、削除済みと同名なら作成可能、削除済み同士は再作成可能）
- カテゴリ名の文字数制約（1〜50文字、記号を含む名前も許可）
- 存在しない/削除済みカテゴリへの操作が404になること

### test_study_records.py（35件）：学習記録CRUD・検索

- 登録の正常系・異常系（CSRF必須、認証必須、存在しない/削除済みカテゴリの拒否、理解度1〜5の範囲チェック、学習時間1〜1440分の範囲チェック、未来日の拒否）
- `user_id`をリクエストボディで上書きできないこと（所有者はログインユーザーで固定されること）
- 詳細取得・編集・削除における所有者確認（他ユーザーの記録への操作は403、論理削除済みは404）
- カテゴリを削除済みのものに変更しようとした場合の拒否、変更しない場合は許可
- 一覧のページネーション（デフォルト10件）、キーワード検索（タイトル・内容の両方に一致）、複数条件のAND検索、学習期間での絞り込み、論理削除済みの除外
- 他ユーザーの記録が一覧に含まれないこと

### test_dashboard.py（13件）：ダッシュボード集計

- 学習記録が0件の場合でもエラーにならず0値で返ること
- 今日の学習時間の集計（他ユーザー・論理削除済みを除外すること）
- 連続学習日数の計算（今日のみ記録がある場合、複数日連続の場合、今日は記録がなく昨日から継続している場合、2日以上の空白でリセットされる場合）
- 日別・カテゴリ別（当月）・月別（直近6か月）の集計範囲
- 最近の学習記録の件数上限と並び順

### test_admin.py（11件）：管理者機能

- ユーザー一覧取得（ADMIN権限必須、認証必須）
- 単一ユーザー取得（正常系、存在しないIDで404、USER権限で403）
- 他ユーザーの学習記録閲覧（論理削除済みの除外、ADMIN権限必須、存在しないユーザーIDで404、ADMIN自身のIDを指定した場合も動作すること）

## Frontendテスト（Vitest + React Testing Library、3ファイル・17件）

Phase 8で、仕様書が重点対象として挙げるコンポーネントに絞ってテストを追加しました。`StudyRecordForm`やページコンポーネント全体は意図的にスコープ外としています（詳細は次節）。

### StarRating.test.tsx（4件）

- `value`に応じた★/☆の表示数が正しいこと
- 選択中の星のみ`aria-checked`が`true`になること
- 星をクリックすると、クリックした星の値で`onChange`が呼ばれること
- `value=0`のとき全て☆で表示されること

### Pagination.test.tsx（8件）

- `totalPages`が1以下・0のとき何も表示されないこと
- 先頭ページで「前へ」、最終ページで「次へ」がそれぞれ無効化されること
- 中間ページでは両方のボタンが有効なこと
- 現在のページ数の表示
- 「前へ」「次へ」クリックで`onPageChange`が正しいページ番号で呼ばれること

### SearchForm.test.tsx（5件）

- マウント時にカテゴリ一覧を非同期取得し、選択肢として表示すること
- カテゴリ取得に失敗した場合にエラーメッセージを表示すること
- 検索条件の送信時、未入力項目が`undefined`として渡されること
- 全項目入力時に入力値がそのまま渡されること
- リセットボタンで入力項目がクリアされ、`onSearch({})`が呼ばれること

## テスト対象外の領域（現時点）

以下はPhase 8のスコープ決定時に、意図的にテスト対象から除外しています。

- **StudyRecordForm**：学習記録登録・編集フォーム本体。バリデーションロジックを内包するが、対象コンポーネントを重点3コンポーネント（StarRating / Pagination / SearchForm）に絞る方針としたため対象外
- **ページコンポーネント**（`dashboard/page.tsx`等）：API通信・状態管理を含む結合的な性質が強く、Backend側のAPIテストで機能的なカバレッジは確保されているため対象外
- **カバレッジ計測**：Vitest/pytestともにカバレッジツールは導入していない。数値目標を追うより重要コンポーネントを適切にテストする方針としている

## CIとの関係

GitHub Actionsで、`main`ブランチへのPull Request作成・更新時に上記の全テストが自動実行されます（`.github/workflows/ci.yml`の`backend`/`frontend`ジョブ）。`main`ブランチのBranch Protection Ruleにより、両ジョブが成功しない限りマージできません。詳細は [README.md のCI/CD節](../README.md#cicd) を参照してください。
